# Codex for Open Source: eligibility self-check

Checked: 2026-08-09

This checklist is not an official scoring system. It is a practical way to
decide whether an application can be supported with credible evidence.

## Strong application signals

- You actively maintain the project rather than only owning the repository.
- People or organizations outside your team use the project.
- The repository has recent releases, issues, pull requests, or security work.
- Other contributors participate in development or maintenance.
- The README explains installation, use cases, governance, and support.
- The project has an explicit open-source license.
- You can explain why the software matters to its users or ecosystem.
- You can describe how Codex or API credits would improve maintenance work.

## Weak signals on their own

- The repository is public.
- The project was recently generated with an AI coding tool.
- Friends added Stars after being asked.
- The repository contains a prototype but has no users or maintenance history.
- The owner has many unrelated repositories.

## Evidence to prepare

- Repository URL and license
- Maintainer role and responsibilities
- Releases and maintenance activity
- Usage, downloads, dependents, deployments, or user references
- Examples of issues, reviews, security fixes, and contributor support
- A concrete six-month maintenance plan

## Decision rule

Apply when the evidence shows both ongoing maintenance and external value. If
those signals are missing, improve the project and document real adoption before
submitting.
