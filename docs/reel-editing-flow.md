## 0. クラウドセッション用の環境差分(このリポジトリで動かす場合)

デスクトップ(Mac)前提の仕様を、クラウドセッション(Linuxコンテナ)で動かすときの読み替え:

| 項目 | デスクトップ版 | クラウド版 |
|---|---|---|
| 素材の受け取り | ローカルファイル | チャット添付 or Google Drive連携で取得 |
| 納品先 | `~/Downloads/` | チャットにファイル送信(SendUserFile)。Driveへの書き戻しも可 |
| フォント | ヒラギノ角ゴシック W6/W7 | **Noto Sans CJK JP**(Regular=W6相当、Bold=W7相当)`/usr/share/fonts/opentype/noto/NotoSansCJK-*.ttc` |
| 文字起こし | whisper.cpp(`~/whisper-models/`) | **faster-whisper**(Python)。発見用 `small`、確定箇所 `large-v3` |
| 量産キット | `~/Downloads/grandma_shorts_kit/build_short.py` | 未移植。必要になったらこのリポジトリの `tools/` に再実装する |
| PiPレシピ | `~/Downloads/grandma_shorts_kit/pip_overlay.md` | 未移植(§2のPiP仕様の要点で代替) |
| セッション初回 | — | `apt-get update && apt-get install -y ffmpeg fonts-noto-cjk && pip install pillow faster-whisper` を実行してから作業開始 |

その他(ffmpeg設定値、字幕PNG方式、尺・フック・カバー・納品セットのルール)は以下すべてそのまま適用する。

## 1. 編集フロー(受け取り→納品)

1. **素材確認**: `ffprobe` で全素材の解像度・尺・回転メタデータ(iPhone縦撮りは rotation -90)を確認。各クリップからサムネイルを抽出し、コンタクトシート(グリッド画像)を自分で目視確認する
2. **文字起こし**(トーク素材の場合): whisper で全体を文字起こし → ハイライト候補をタイムスタンプ付きで特定
3. **【重要】候補・ストーリーボードを先に提示**: いきなり完成品を作らない。カット候補・構成案・使う秒数・テキスト案を表かリストで見せて、選んでもらってから制作に入る。ただし相手が「作ってみて」と言ったら即座にv1を作る(走りながら調整の文化)
4. **確定素材の高精度化**: 採用が決まった箇所だけ大きいwhisperモデルで再文字起こしして字幕の正確性を上げる(誤変換は文脈で修正: 例「秋が来ない」→「飽きが来ない」)
5. **ビルド**: セグメント切り出し→連結→字幕/フックPNG焼き込み→最終エンコード
6. **セルフチェック**: 完成品から4〜10フレームを抽出して目視確認(字幕見切れ・カットの弱い絵・テキスト表示漏れを自分で見つけて直してから納品する)
7. **納品**: `~/Downloads/` にコピーし、投稿セット一式(§4)を添えて報告
8. **修正**: カット単位で差し替えられる構造にしておき、修正は数分で回す

## 2. 編集仕様

### 尺
- トーク系ショート: **45〜55秒目標**(最短30秒、最長65秒まで許容)
- Vlog/モンタージュ: **30〜50秒**
- カット基準: whisperのタイムスタンプに **前後0.3〜1.0秒のパディング**。フィラー(うん、あの)、内輪ネタ、宗教的言及はカットで抜く。台詞の途中で切らない
- 長い素材は複数セグメント切り出し→concat。カットは基本ハードカット

### 映像フォーマット
- **1080x1920 (9:16縦) / 30fps / H.264 / yuv420p**
- 中間セグメント: `-preset veryfast -crf 19` (or 18)
- 最終書き出し: `-preset medium -crf 18〜19 -movflags +faststart`
- 音声(トーク系): AAC 160k / 48kHz / stereo(元音声を維持)
- 音声(音楽前提のvlog): **無音AACトラックを付与**(`-f lavfi -i anullsrc=r=48000:cl=stereo` + `-c:a aac -b:a 96k -shortest`)。音楽はアプリ側で載せる方針のためBGMは焼き込まない
- Vlogは全体をウォーム系に統一: `eq=saturation=1.05:brightness=0.008,colorbalance=rm=.04:bm=-.04`
- ノスタルジック演出: 本編0.9倍スロー(`setpts=PTS/0.9`)、フェードイン0.25秒・フェードアウト0.8秒
- 静止画の動画化: zoompan でKen Burns(手ブレ素材のプロダクトカット等に使う)

### 字幕(焼き込み・Pillow PNG方式)
ffmpegがlibass無しビルドでも動くよう、**PillowでPNG生成→overlayフィルタ**で焼く。

- **日本語(上段)**: ヒラギノ角ゴシック W6、46px、黄色 `(255,224,102)`、ストローク5px黒
- **英語(下段・メイン)**: ヒラギノ角ゴシック W7、60px、白、ストローク7px黒
- 位置: **下から1/3、ブロック下端 y=1560 アンカー**(スマホUI回避)、中央揃え、自動改行(画面幅-60px)
- 表示タイミング: 台詞のwhisperタイムスタンプに同期、1キュー=1文(長文は分割)。キュー間の隙間は最小限
- **フックテキスト(冒頭)**: 画面上部 y=220〜430、英語 64px W7 白 + 日本語 44px 黄、表示は最初の5〜6.4秒
- **全テキストに自動縮小(auto-fit)必須**: 幅超過なら2pxずつ縮小。見切れは過去に2回起きた既知の事故

### フック(冒頭3秒)の方針
- トーク系: 冒頭に質問→回答の強い2キュー + 上部フックテキスト(例: "My grandma is 91." 系の数字フック)
- Vlog系: **0.75秒×4連発のフラッシュフォワード**(ベストカット4つ)→ 3.0秒でビート頭、本編へ。音楽同期はこの3.0秒地点をユーザーに伝える
- フックの文言は「数字(91歳、68年、6,000マイル)+ JAPAN + grandma」系のワードが強い

### カバー画像(1080x1920 JPG)
- ベース: 動画のベストフレーム(表情・ジェスチャー重視)。**顔が映るフレーム優先**
- 上部にグラデーション(黒α150〜185、y=0→830-900)を敷く
- テキスト: W7、白メイン+**強調1〜2ワードを黄色`(255,214,64)`**、サイズ80〜132px、ストローク size//8
- **赤丸バッジ**(`(214,40,57)` rounded_rectangle、白太字50前後px): サブ情報「from my 91-year-old grandma」等
- 全テキストはIGグリッド1:1クロップ安全域(y420〜1500)内
- 複数案(2〜3枚)を比較画像で見せてから決定

### PiP引用演出(語り動画で過去リールを引用)
角丸マスク(radius 28)+白フチframe PNG+alphamerge+overlay。幅40%(432x768)。
**`-loop 1` には必ず `-t` を付ける(付けないとffmpegハング)**。詳細レシピは `~/Downloads/grandma_shorts_kit/pip_overlay.md`。

## 3. ツール・コマンド

- **ffmpeg**: 上記設定値。`-nostdin` をループ内では必須(stdin食い事故防止)
- **whisper.cpp**: 発見用 `ggml-small`、確定箇所の高精度化 `ggml-large-v3-turbo`(モデルは `~/whisper-models/`)。Apple SiliconでHomebrewがIntel版の環境ではネイティブビルドしないと6倍遅い(`cmake -DGGML_NATIVE=OFF -DCMAKE_OSX_ARCHITECTURES=arm64 -DGGML_METAL=ON`)
- **Pillow**(/usr/bin/python3): 字幕・フック・カバー・マスク全てのテキスト/図形描画
- **量産キット**: `~/Downloads/grandma_shorts_kit/build_short.py` — spec JSON({name, segments, cues, hook})を書いて実行すると切り出し→字幕→書き出しまで自動。新しいショートはまずこれで作る
- 音声抽出: `-vn -ac 1 -ar 16000 -c:a pcm_s16le`(whisper用16kHz mono WAV)

## 4. 納品形式

- 保存先: `~/Downloads/`(ユーザーは後で `Grandma series/` 等のフォルダに整理することがある)
- ファイル名: 英語スネークケースで内容がわかる名前 + 版数
  - 動画: `grandma_short_D_wisdom.mp4`, `kagoshima_reel_v4.mp4`
  - カバー: `D_cover_longevity.jpg`, `vlog_cover_final.jpg`
- **納品は「投稿セット」単位**。動画だけ渡さない:
  1. 動画ファイル
  2. カバー画像
  3. IGキャプション(コピペ可能なコードブロックで)
  4. 固定コメント(同上)
  5. 投稿チェックリスト(位置情報 Kagoshima, Japan / 音源の載せ方とビート合わせ地点 / 投稿時刻)
- キャプション構成: ①1行目フック(折りたたみ前提) ②名言引用ブロック ③本人の一言 ④質問CTA👇 ⑤🇯🇵日本語補足3文 ⑥ハッシュタグ7個(内容連動)
- 投稿時刻の推奨: **17:00 PT(=20:00 ET)**、ユーザーはLA在住なのでPT基準で話す

## 5. ユーザーの修正指示の傾向・好み

- **「候補をまず見せて」**: 完成品の前にテキスト/表で選択肢を見たい。ただし選択肢は3〜5個まで+推奨1つを明示(選択肢を並べすぎない)
- **「もっとインパクト」**: 文字を大きく、強ワード(JAPAN / longevity / 数字)を足す、強調色・赤バッジを使う方向で直す
- **「顔を見せた方がいい」**: カバーは風景より顔。「顔で興味→キャプションでクリック」の思想
- **「端的に短く」**: 固定コメントや説明文は3行以内に削られがち。初稿から短めに
- **「91-year-old grandma」というフレーズを好む**(数字入りの具体性)
- **個人ブランドとのバランスに敏感**: grandmaコンテンツが多すぎると「おばあちゃんアカウントになる」と嫌がる。founder(CEO)としてのブランディングが最優先。コンテンツ提案時はこのバランスに言及すること
- 英語コピーのトーン: 短文の言い切り。"Not as a trend — as an inheritance." のような対句を好む
- 誤変換の指摘に敏感(字幕の正確性)。納品前に高精度モデルで確認するのはこのため
- スピード重視。「作ってみよう」と言われたら即v1を出し、フィードバックで直す
- 深追いデバッグより確実な代替策(例: enableタイミングが不発→クリップに直接焼いて再連結)を好む
