# Public-release checklist

Use this checklist before every public commit or release.

## Company and partner information

- [ ] No non-public company plans, strategy, financials, forecasts, or metrics
- [ ] No customer, client, vendor, manufacturer, agency, or partner information
- [ ] No internal meeting notes, decisions, screenshots, links, or file names
- [ ] No statements presented as the view of an employer or officer role

## Security and privacy

- [ ] No email addresses, phone numbers, addresses, or private identifiers
- [ ] No passwords, tokens, API keys, cookies, credentials, or environment files
- [ ] No private repository names, organization details, or access information
- [ ] No personal application data or browser/account screenshots

## Accuracy and rights

- [ ] Claims are linked to primary sources and include a checked date
- [ ] Facts, interpretation, and unverified claims are clearly separated
- [ ] Third-party text, images, code, and trademarks are used lawfully
- [ ] The note includes an appropriate disclaimer where confusion is possible

## Git check

- [ ] Review every staged file and the complete diff
- [ ] Search the full reachable history for secrets and private identifiers
- [ ] Confirm the commit uses a public-safe author name and noreply email
